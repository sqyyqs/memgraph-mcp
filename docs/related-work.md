Поисковой запрос: `multi-agent semantic knowledge graph provenance`
Рассматриваемый 3 аналог - OSS проект Semantica

## Критерии

### Наличие графовой памяти.

1) Mem0 Platform - есть граф сущностей и записей
2) Graphiti - использует граф
3) Semantica - работает только с графом

### Типизированные отношения между фактами

1) Mem0 Platform - не использует связи между сущностями.
2) Graphiti - отношения между сущностями.
3) Semantica - отношения между сущностями.

### Хранение автора каждого факта

1) Mem0 Platform - `agent_id` задаёт область/привязку памяти, но документация не подтверждает, что это автор
   каждого извлечённого факта.
2) Graphiti - факт хранит UUID исходных эпизодов, но обязательного поля автора или `agent_id` у факта и эпизода нет.
   Автор восстанавливается только в том случае, если клиент сам записал его в содержимое или описание источника.
3) Semantica - `ProvenanceEntry` содержит `agent_id`, однако это поле библиотечного provenance API; в MCP оно не
   экспортировано как автор факта.

### Хранение источника каждого факта

1) Mem0 Platform - может хранить `source` в `metadata` по соглашению клиента; first-class связь факта с источником
   не подтверждена.
2) Graphiti - у `EntityEdge` есть список `episodes`, а эпизод хранит `source` и `source_description`: подтверждён
   путь fact → episode → source, но не путь к автору.
3) Semantica - `ProvenanceManager` хранит документ, позицию и цитату источника в Python API; через MCP эти операции
   не доступны.

### Хранение даты события

1) Mem0 Platform - может хранить дату события в `metadata`, есть фильтры на поиск.
2) Graphiti - есть поля `valid_at`, `invalid_at`, `reference_time`
3) Semantica - есть специальны временные метки: `valid_from`, `valid_until`

### Хранение даты записи

1) Mem0 Platform - хранит.
2) Graphiti - есть поле `created_at`.
3) Semantica - есть специальны временные метки: `recorded_at`, `superseded_at`

### Запрос состояния на момент t

1) Mem0 Platform - интервалы можно моделировать полями `valid_from` и `valid_until` в `metadata`. Для полуоткрытого
   интервала `[valid_from, valid_until)` факт действует в момент `t`, если `valid_from ≤ t` и одновременно
   `valid_until > t` либо верхняя граница отсутствует. Не подтверждено, что фильтры Platform выражают весь этот
   предикат, включая открытую верхнюю границу, и выполняют его эффективно. Само хранение дат в `metadata` не
   создаёт исторические версии факта: версии и правила их закрытия должен поддерживать клиент или сервер.
2) Graphiti - MCP-поиск предоставляет диапазонные фильтры по `valid_at`/`invalid_at`, но отдельной атомарной
   операции `state_at(t)` нет; эквивалентность комбинации фильтров историческому снимку не проверена.
3) Semantica - есть специальные типы запросов: `TemporalGraphQuery`, нет в MCP.

### Общая память нескольких агентов

1) Mem0 Platform - есть области доступа.
2) Graphiti - есть концепция graph-namespacing, поддерживается разделение по `group_id`. Если нужно связать память для
   нескольких агентов, можно задать им один `group_id`
3) Semantica - MCP работает с общим настроенным графом; отдельный namespace или ACL для нескольких агентов не
   подтверждён.

### Обнаружение конфликтов

1) Mem0 Platform - LLM-судья может удалить/добавить ноды
2) Graphiti - инвалидирует записи которые не соответствуют новым фактам путем установки у них `expired_at`
3) Semantica - в Python API `ConflictDetector` реализует value, type и relationship conflicts, а
   `ConflictResolver` предлагает автоматические и ручные стратегии. `TEMPORAL` и `LOGICAL` присутствуют в enum,
   но их непосредственное обнаружение не реализовано. Conflict-инструменты не входят в опубликованный MCP API
   ([документация
   `v0.7.0`](https://github.com/semantica-agi/semantica/blob/v0.7.0/docs/reference/conflicts.md#conflictdetector)).

### Ограничение выдачи бюджетом токенов

1) Mem0 Platform - не удалось подтвердить.
2) Graphiti - есть параметр `limit`, привязанный к числу нод, не токенов.
3) Semantica - есть параметр `limit`, привязанный к числу нод, не токенов.

### Открытый исходный код

1) Mem0 Platform - есть 2 вариации: OSS + Platform, последняя не открытое ПО.
2) Graphiti - да.
3) Semantica - да.

### MCP-интерфейс

1) Mem0 Platform - есть.
2) Graphiti - есть с ограниченной функциональностью.
3) Semantica - есть с ограниченной функциональностью.

Mem0, Graphiti и Semantica используют разные подходы к хранению информации: Mem0 сохраняет отдельные воспоминания,
Graphiti работает с графом знаний и временем действия фактов, а Semantica предоставляет в Python-библиотеке
provenance и обнаружение value/type/relationship conflicts. Temporal/logical detectors у Semantica не реализованы,
а provenance, temporal query и conflict API не опубликованы как MCP-инструменты.

Однако не все эти функции доступны напрямую через MCP, а возможность извлекать связанный подграф с ограничением по
количеству токенов не подтверждена ни в одной из рассмотренных систем.

Хорошей отправной точкой в нашем проекте можно считать возможность объединить этот функционал в одном MCP-сервере на
основе Neo4j, добавив темпоральные запросы, проверку конфликтов при записи и контроль размера выдаваемого подграфа.
В дальнейшем мы проверим, как эти механизмы влияют на точность ответов агентов, обнаружение противоречий и расход
токенов.
